# imgsorter-app — Phase 5 Design: Real Thumbnails/Previews + Opt-In Setting

**Date:** 2026-10-04
**Status:** Draft for review
**Scope:** Phase 5 only — show real previews in the file preview drawer and the Overview
largest-files list, generated by the server with `sharp` and cached on disk, behind a new
opt-in setting that is **off by default**, with controls in Preferences and on the Overview
page. This closes the roadmap.

## 1. Context & source material

Two places show decorative placeholder pictures today:

- `app/components/common/FilePreviewDrawer.tsx` renders the selected file's preview as a
  `background-image` from the six Unsplash URLs in `app/lib/placeholder-thumbs.ts`.
- `app/features/overview/OverviewPage.tsx` renders the largest-files list with the same URLs.

The Files/Browse/Duplicates tables show **no** images, so they are out of scope.

**Constraints found while exploring:**

- The photo DB holds the real file `path` for every indexed entry. The app has no image code.
- `better-sqlite3` is already a server-only native dependency; the build forces server-only code
  out of `dist/client`.
- `server/lib/native-actions.ts` is the pattern for a server-only module with an injectable
  factory plus a singleton and an injected seam for tests.
- `ApplicationConfig` (in `app/lib/types.ts`) holds the persisted Preferences toggles; the
  Preferences "Application configuration" tab edits them via `saveApplicationSettings`.
- `@tanstack/react-start/server-only` and dynamic imports keep server modules out of the client
  bundle.

**Decisions made during brainstorming:**

- **Previews for the drawer and the Overview list only.** No table thumbnails.
- **`sharp`** resizes images to a 256px-wide WebP; the result is cached on disk.
- **Disk cache** at `server/data/thumb-cache/` (gitignored), keyed by path, size, and mtime.
- **Images only** (`.jpg`, `.jpeg`, `.png`, `.gif`, `.webp`); videos and unreadable files show a
  neutral icon.
- **Delivery: a `getThumbnails` server function** returns base64 data URLs. No HTTP route.
- **New setting `generatePreviews`, off by default.** Off still serves cached previews; it stops
  new generation only.
- **Controls in both places:** a switch in Preferences (saved with the form) and a quick switch
  on the Overview page (autosave). A "Clear preview cache" action lives in Preferences.

## 2. Goals

- The drawer and the Overview list show the real image for a file, or a neutral icon.
- Previews are small and fast; repeated views reuse the disk cache.
- Preview generation is **off by default** and can be turned on or off at runtime.
- Turning it off stops new generation but keeps already-cached previews.
- The cache can be cleared.
- Keep `sharp` and `better-sqlite3` server-only.

## 3. Non-goals (Phase 5)

- No video poster frames (no ffmpeg).
- No previews in the Files/Browse/Duplicates tables.
- No client-side image generation.
- No multiple preview sizes and no cache size limit.
- No change to the scan or the engine.

## 4. Technology

Unchanged: TanStack Start (`createServerFn`, route loaders), React 19, Mantine v9,
`@mantine/notifications`, `better-sqlite3` (server-only), Vitest (client jsdom / server node),
TypeScript strict. Added: `sharp` (server-only native module).

## 6. Data model & storage

### 6.1 `app/lib/types.ts`

```ts
export type ThumbnailMap = Record<number, string>;
```

`ApplicationConfig` gains one field:

```ts
export type ApplicationConfig = {
  extensions: string;
  processDirectories: boolean;
  updateRecords: boolean;
  resyncDirectories: boolean;
  verifyFiles: boolean;
  generatePreviews: boolean;
};
```

### 6.2 Settings (`app/lib/app-config-defaults.ts`, `server/lib/app-config.ts`)

- `DEFAULT_APP_CONFIG.application.generatePreviews = false`.
- `normalizeApplication` adds `generatePreviews: Boolean(input.generatePreviews)`.
- `isApplicationConfig` checks `typeof value.generatePreviews === 'boolean'`. A stored value
  without the field reads as the default (`false`) and is rewritten.

### 6.3 Cache folder (`app/lib/db-path.ts`)

- `thumbCacheDir(): string` → `join(serverDir, 'data', 'thumb-cache')`.
- `.gitignore` ignores `server/data/thumb-cache/`.

### 6.4 Cache key

`sha256(`${normalizeDirectoryPath(path).toLowerCase()}:${size}:${mtimeMs}`).toString('hex')`.
Cache file: `<thumbCacheDir>/<key>.webp`. A changed file (new size or mtime) gets a new key, so
its preview refreshes naturally.

## 7. Thumbnail service (`server/lib/thumbnails.ts`)

`import '@tanstack/react-start/server-only';`

Small, testable pieces:

- `IMAGE_EXTENSIONS = ['.jpg', '.jpeg', '.png', '.gif', '.webp']`.
- `THUMB_WIDTH = 256`, WebP quality `75`, `fit: 'inside'`, `withoutEnlargement: true`.
- `type ThumbnailDeps = { cacheDir: string; getEntryPath: (id: number) => string | null;
  statFile: (path: string) => { size: number; mtimeMs: number } | null;
  resize: (path: string) => Promise<Buffer>; readCache: (file: string) => Buffer | null;
  writeCache: (file: string, data: Buffer) => void; readSetting: () => boolean;
  removeCacheFiles: () => number; }`.
- `createThumbnailService(deps): { getThumbnails(ids: number[]): Promise<ThumbnailMap>;
  clearCache(): number }`.
- `export const thumbnails = createThumbnailService({ ...real deps... })`.

`getThumbnails(ids)`:

1. Read `enabled = deps.readSetting()` once.
2. For each id:
   - `stored = deps.getEntryPath(id)`; skip when `null`.
   - `realPath = stored.startsWith('@fixtures') ? virtualToReal(stored) : stored`.
   - Skip when the extension is not in `IMAGE_EXTENSIONS`.
   - `stat = deps.statFile(realPath)`; skip when `null`.
   - `file = join(cacheDir, key + '.webp')`; `cached = deps.readCache(file)`.
   - A cached buffer is returned as a data URL (this happens even when disabled).
   - Else, when `enabled`, `data = await deps.resize(realPath)`; `deps.writeCache(file, data)`;
     return the data URL. A thrown error skips the id.
   - Else (disabled and no cache) skip the id.
3. Return the map.

`clearCache()` calls `deps.removeCacheFiles()` and returns the count.

Data URL: `data:image/webp;base64,${buffer.toString('base64')}`.

## 8. Server routes

### 8.1 `server/routes/thumbnails.ts` (new)

```ts
export const getThumbnails = createServerFn({ method: 'POST' })
  .validator((input: { ids: number[] }) => input)
  .handler(async ({ data }) => {
    const { thumbnails } = await import('../lib/thumbnails');
    return thumbnails.getThumbnails(data.ids);
  });

export const clearThumbnailCache = createServerFn({ method: 'POST' }).handler(async () => {
  const { thumbnails } = await import('../lib/thumbnails');
  return { removed: thumbnails.clearCache() };
});
```

### 8.2 `server/routes/preferences.ts`

Add:

```ts
export const setPreviewsEnabled = createServerFn({ method: 'POST' })
  .validator((input: { enabled: boolean }) => input)
  .handler(async ({ data }) => {
    const { appConfigStore } = await import('../lib/app-config');
    const config = appConfigStore.get();
    const saved = appConfigStore.saveApplication({ ...config.application, generatePreviews: data.enabled });
    return { enabled: saved.application.generatePreviews };
  });
```

### 8.3 `server/routes/overview.ts`

Return the setting with the stats:

```ts
export const getOverviewData = createServerFn({ method: 'GET' }).handler(async () => {
  const { getOverviewStats } = await import('../lib/queries');
  const { appConfigStore } = await import('../lib/app-config');
  return { data: getOverviewStats(), previewsEnabled: appConfigStore.get().application.generatePreviews };
});
```

`app/routes/index.tsx` passes `data` and `previewsEnabled` to `OverviewPage`.

## 9. Client

### 9.1 `FilePreviewDrawer.tsx`

- Keep the selected file's preview in state, for example `thumb: string | null`.
- On a change of `selectedFile`, when there is one, call `getThumbnails({ data: { ids: [id] } })`
  and set `thumb` to the result or `null`. A failed call sets `null`.
- Render the `drawer-thumb` with the data URL when present; otherwise render a neutral placeholder
  (a `FileImage` icon on a dimmed background).
- The drawer no longer imports `thumbs`.

### 9.2 `OverviewPage.tsx`

- Props: `{ data: OverviewData; previewsEnabled: boolean }`.
- Keep `thumbById: ThumbnailMap` and `enabled` state seeded from `previewsEnabled`.
- On mount and when `data.largestFiles` or `enabled` change, call
  `getThumbnails({ data: { ids: data.largestFiles.map((e) => e.id) } })` and set the map. A
  failure keeps an empty map.
- Render each largest file's preview from the map; otherwise a placeholder icon.
- Add a `Switch` next to the "Largest files" heading:
  - `checked={enabled}`;
  - on change, call `setPreviewsEnabled({ data: { enabled } })`; on success set `enabled` (which
    refetches previews); on failure show a red toast and keep the old value.
- The page no longer imports `thumbs`.

### 9.3 `PreferencesPage.tsx`

- The application form includes `generatePreviews`. Add a switch row "Generate thumbnail previews"
  with helper text that it is off by default and that cached previews still show when off.
- Add a "Clear preview cache" button near the switch that calls `clearThumbnailCache` and shows a
  short toast: `Preview cache cleared (N files).` On failure, a red toast.
- "Save preferences" persists `generatePreviews` with the rest, as today.

## 10. Lifecycle / data flow

1. Open the Overview or the drawer → the client calls `getThumbnails`.
2. The server serves a cached preview, or generates one when the setting is on, or returns nothing.
   The UI shows the image or the icon.
3. Flip the Overview switch → `setPreviewsEnabled` → `app-config.db` → refetch previews.
4. "Save preferences" persists the Preferences switch.
5. "Clear preview cache" deletes the cache files; previews regenerate only when the setting is on.
6. The setting and the cache survive a reload, a server restart, and `pnpm seed`.

## 11. Testing & verification

  - a cache hit returns the cached data URL and does not call `resize`;
  - a miss with the setting on calls `resize` and writes the cache;
  - the setting off with no cache returns nothing for that id;

## 13. Trade-offs & follow-ups

- `sharp` is a second server-only native dependency. The build check guards leaks, as it does for
  `better-sqlite3`.
- The cache has no size limit; it grows with the number of distinct files previewed. A future
  cleanup can add an eviction policy.
- Previews are opt-in, so a fresh install shows icons until the user turns them on.
- Off still serves cached previews; a user who wants a clean slate uses "Clear preview cache".
- Videos keep the icon; a future phase could add poster frames with ffmpeg.
