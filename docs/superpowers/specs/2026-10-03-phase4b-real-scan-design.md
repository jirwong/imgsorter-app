# imgsorter-app — Phase 4b Design: Real Configured-Directory Scan + Per-Directory Stats

**Date:** 2026-10-03
**Status:** Draft for review
**Scope:** Phase 4b only — make the UI "Scan library" scan the **real** enabled indexed
directories from `app_config` (minus ignored), **incrementally**, honoring the application
settings; record a per-directory `lastScannedAt`; and show real per-directory file counts +
last scan in Preferences. Split the app DB (local) from a committed test-fixture DB.
Reveal/Open + folder picker (4c) and keeper persistence (4d) are out of scope.

## 1. Context & source material

Phase 4a persisted Preferences (directories + application settings) in a dedicated,
scan-proof `server/data/app-config.db`. Phase 3b drives the vendored engine from the UI, but
the scan is **fixture-driven**: `server/lib/scan-runner.ts` generates the fixture tree, deletes
the DB, runs the engine, rewrites paths to `@fixtures/…` with synthetic birthtimes, and
rebuilds `records`. `pnpm seed` uses the same path, writing the committed
`server/data/imgsorter.db` that `server/lib/queries.ts` reads and `queries.test.ts` asserts.

**Constraints found while exploring:**

- The seeded default directories (`C:/Media/2025`, `D:/Camera Imports`) **do not exist**, so a
  real scan must handle missing/no configuration gracefully.
- The engine's ignore matching is **exact-path** (`iterate-directories.ts` `isIgnored`, and
  `listFilesRecursive` per-subdirectory); there are no recursive/glob ignores.
- `mapPathToDisplay` only relabels `@fixtures/...`; real paths pass through unchanged.
- The engine upserts entries (`ON CONFLICT(path)`) and only removes stale entries in the
  `resync` phase — so a real scan need not delete the DB.
- With an **empty** extensions array the engine includes **all** files
  (`listFilesRecursive`: `normalizedExtensions.length > 0` gates filtering).

**Decisions made during brainstorming:**

- **Real configured dirs only**; no fixture fallback in the UI scan.
- **Split DBs:** app DB becomes local/gitignored; a committed `fixture.db` serves tests; the
  query layer's DB path is env-overridable.
- **Per-dir stats:** file count derived from `entries`; `lastScannedAt` stored per path in a
  separate `app_config` key (`directory_meta`) so directory autosave can't clobber it.
- **Incremental scan** (no DB delete); the "Resync directories" toggle removes stale entries.
- **Refuse** a scan when no directories (or no extensions) are configured; no DB change.
- **Fresh-install defaults:** empty indexed/ignored dirs; keep the app-setting defaults.
- **Recency/stats shown in Preferences only** (Overview `LastRunCard` / Footer mock left as a
  later cleanup).
- **`pnpm seed` regenerates the fixture DB only**; the app DB starts empty.

## 2. Goals

- "Scan library" scans the real enabled indexed directories, minus ignored, using the
  configured extensions and toggles.
- The scan is incremental and cannot wipe the library because of a missing/unreadable root.
- Each scanned directory records a `lastScannedAt`; Preferences shows real `N files · Last
  scan …` per directory.
- The app DB is local state; a committed fixture DB keeps tests fast and deterministic.
- Keep the engine/`better-sqlite3` server-only; keep `pnpm seed` behavior for tests.

## 3. Non-goals (Phase 4b)

- No Reveal/Open or native folder picker (4c); no keeper persistence (4d).
- No ScanHistory table or per-phase timing UI; no Overview/Footer last-run wiring.
- No remote/UNC/symlink-specific handling; no recursive ignore patterns.
- No change to the fixture content/shape or the app_config save model (4a).

## 4. Technology

Unchanged: TanStack Start (`createServerFn`, route loaders), React 19, Mantine v9,
`better-sqlite3` (server-only), Vitest (client jsdom / server node), TypeScript strict.

## 6. Data model & storage

### 6.1 Databases

- **App DB** `server/data/imgsorter.db` — local state, **gitignored**. Holds `entries` +
  `records`. Read by the app; written by real scans. May not exist yet.
- **Fixture DB** `server/data/fixture.db` — committed; used only by tests; regenerated by
  `pnpm seed`. Contains the deterministic fixture data (1272 files / 24 groups).
- `server/lib/db-path.ts`: `sampleDbPath()` (unchanged) = app DB; add `fixtureDbPath()` =
  `server/data/fixture.db`.
- **Path override:** `server/lib/queries.ts` resolves its read path as
  `process.env.IMGSORTER_DB_PATH ?? sampleDbPath()`. The vitest **server** project sets
  `IMGSORTER_DB_PATH` to the absolute `fixture.db`; the client project is unaffected.

### 6.2 Missing/empty app DB

- `openReadonly()` returns `null` when the resolved DB file does not exist.
- Every query returns its **empty shape** when the DB is absent (e.g. `{ files: 0, size: 0,
  roots: [], extensions: [], duplicateGroups: 0 }`, `[]`, empty rankings) so fresh installs
  render zeros instead of crashing.

### 6.3 `directory_meta` (in `app_config.db`)

- New key `directory_meta` → `Record<string, { lastScannedAt: string }>`, keyed by the
  **lowercased normalized path**.
- `app/lib/types.ts` gains `DirectoryMeta` and `AppConfig.directoryMeta: DirectoryMeta`.
- `server/lib/app-config.ts`:
  - reads/validates `directory_meta` (default `{}`) into `AppConfig.directoryMeta`;
  - `recordScannedDirectories(paths: string[], at: string): AppConfig` merges entries;
  - `saveDirectories` / `saveApplication` never write `directory_meta`.
- Removed directories' meta is left in place (harmless; only configured dirs are displayed).

## 7. Server changes

### 7.1 Fixture seed targets the fixture DB

- `runFixtureScan({ progress, signal, dbPath })` gains a `dbPath` parameter (default
  `sampleDbPath()`); behavior otherwise unchanged.
- `scripts/seed.ts` calls it with `fixtureDbPath()`.

### 7.2 `server/lib/scan-configured.ts` (new)

```ts
export class NoDirectoriesConfiguredError extends Error { ... }

export async function runConfiguredScan({ progress, signal }: RunFixtureScanDeps): Promise<RunSummary>
```

- Reads config via `appConfigStore.get()`.
- `directories` = enabled indexed paths; `ignore_directories` = ignored paths.
- `extensions` = parse `application.extensions` (split on `,`, trim, drop blanks, lowercase,
  prefix `.`).
- **Refuse** (throw `NoDirectoriesConfiguredError`) when there are no enabled directories or
  no extensions — the scan does not run and the DB is unchanged.
- `RunConfiguration`: `dbName: sampleDbPath()`, `update_records`, `process_directories`,
  `resync_directories`, `resync_check_actual_file = verifyFiles`.
- Runs `Runner` (silent reporter) **without deleting the DB**; on success calls
  `appConfigStore.recordScannedDirectories(directories, new Date().toISOString())` and returns
  the summary. `RunAbortedError` propagates (no meta recorded).
- Reuse the silent reporter + `Runner` try/finally pattern from `scan-runner.ts`.

### 7.3 Scan service & server fns

- `server/lib/scan.ts`: app singleton becomes
  `createScanService(({ progress, signal }) => runConfiguredScan({ progress, signal }))`. The
  existing `.catch` maps `RunAbortedError` → `cancelled` and anything else → `error` with the
  thrown message ("No enabled directories configured"), so no service change beyond the wiring.
- `server/routes/scan.ts` is unchanged.

### 7.4 Queries

- `countEntriesByDirectory(root: string): number` — count entries whose directory equals the
  root or is beneath it, **separator- and case-insensitively**. Because stored directories use
  OS separators, compare via
  `lower(replace(directory, char(92), '/'))` against the normalized root and `root || '/%'`
  (escape `\`, `%`, `_`).

## 8. Client changes

- `server/routes/preferences.ts` adds `getPreferencesData` (GET) returning
  `{ config: AppConfig, counts: Record<string, number> }` (config from `appConfigStore.get()`,
  counts via `countEntriesByDirectory` over the indexed roots).
- `app/routes/preferences.tsx`: loader returns `getPreferencesData()`; pass `config` and
  `counts` to the page.
- `app/features/preferences/PreferencesPage.tsx`: each indexed row renders
  `N files · Last scan <time>` from `counts[path]` and
  `config.directoryMeta[normalizedPath]?.lastScannedAt` — or `Not scanned yet` when absent. A
  small `formatScanTime(iso)` helper renders the timestamp.
- No new refresh plumbing: `ScanRevalidator` already `router.invalidate()`s on a terminal
  scan, so the loader re-runs and stats update.

## 9. Lifecycle / data flow

1. Configure real directories in Preferences (persisted in `app_config.db`).
2. "Scan library" → `runConfiguredScan` reads config, builds `RunConfiguration`, runs the
   engine incrementally over the enabled roots (minus ignored), records `lastScannedAt`.
3. `ScanRevalidator` invalidates on completion → Overview/Duplicates/shell + the Preferences
   loader re-read the app DB and `directory_meta`.
4. Preferences shows real per-directory counts and last-scan times.
5. `pnpm seed` regenerates `fixture.db` only; the app DB is untouched.

## 10. Testing & verification

- **`server/lib/db-path.test.ts`:** `fixtureDbPath()` under `server/data`.
- **`server/lib/queries.test.ts`:** reads the fixture DB via the vitest env override; totals
  unchanged. Add `countEntriesByDirectory` cases (root, nested, separator/case-insensitive).
- **`server/lib/app-config.test.ts`:** `directory_meta` defaults to `{}`; `recordScannedDirectories`
  round-trips and merges; `saveDirectories` leaves `directory_meta` intact.
- **`server/lib/scan-configured.test.ts` (new, node):** builds `RunConfiguration` from a
  temp app-config store (paths/extensions/toggles) and throws
  `NoDirectoriesConfiguredError` for no dirs / no extensions. Inject the runner/engine seam so
  the test does not touch the filesystem (mirror `scan.test.ts`'s injected-fake approach).
- **Missing-DB tolerance:** a `queries` test pointing at a nonexistent path returns empty
  shapes.
- **Client (`PreferencesPage.test.tsx`):** renders real `N files · Last scan …` /
  `Not scanned yet` from supplied `counts` + `directoryMeta`.
- **Gates:** `pnpm typecheck && pnpm lint && pnpm test && pnpm format:check`; `pnpm build`
  (no `better-sqlite3`/`sqlite` in `dist/client`).
- **Manual smoke:** add a small real folder with a few images, scan, and verify the library,
  duplicates, and per-directory stats; run `pnpm seed` and confirm the app DB is untouched.
  Restore/remove local state afterward.

## 12. Trade-offs & follow-ups

- The app DB is gitignored: a fresh clone shows an empty library until a scan. `pnpm seed` no
  longer provides a demo library for the running app.
- The DB path override is process-wide (`IMGSORTER_DB_PATH`); server tests share the
  read-only fixture DB (fine).
- `directory_meta` grows with removed paths (not pruned); harmless.
- Large real folders make scans slow and hash-heavy (expected; the engine hashes file edges).
- Overview `LastRunCard` / Footer still show static mock text — a later cleanup.
- Phase 4c adds Reveal/Open + the native folder picker; 4d adds keeper persistence.
